# Contributing to Tyche Bonds

Tyche Bonds is one of three repositories that share these rules: Stoa,
the design system, and the two products built on it, Ariadne Desk and
Tyche Bonds. The Tyche specifics follow the shared rules.

## Text

- No emojis anywhere: code, comments, docs, commit messages, pull request
  text.
- No attribution trailers, "generated with" or "generated by" lines or
  session links in commits, pull request text, code or docs. Commit
  messages and pull request text describe the change only.
- Plain, specific sentences, without redundant em dashes. Code, comments
  and repository docs in English. The interface words exist in Russian, the
  default, and English.
- Public text names no internal material: plans, audits, roadmap phases,
  people, pricing or hiring.
- `scripts/check-text.mjs` enforces emojis, attribution and internal paths
  on the tracked files, the commit messages and the pull request text, in
  CI and locally.

## Commits, branches, pull requests

```
<type>(<scope>): <short description>
```

Types: feat, fix, refactor, test, docs, chore. Scopes: terminal (the app),
yield (the bond engine), twin (its TypeScript twin), market (the market
engine), tyche (repository-wide).

- Work on a branch; `main` changes only through a pull request with green
  CI, merged with a merge commit; the branch is deleted after the merge.
- One concern per pull request; a fix comes with a test that fails
  without it.

## Acceptance

Acceptance is the full CI command list, run locally; compiling is not
passing. The app links Stoa from a sibling checkout, so clone
[stoa](https://github.com/ghostjima/stoa) next to this repository and
build it first (`pnpm install --frozen-lockfile && pnpm build` in
`../stoa`). Then, from the repository root, run and pass:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy --workspace --all-targets --locked --no-default-features -- -D warnings
cargo clippy --workspace --all-targets --locked --features wasm -- -D warnings
cargo clippy --workspace --all-targets --locked --all-features -- -D warnings
cargo test --release --locked -p tyche-yield
cargo test --release --locked -p tyche-market
cargo test --workspace --release --locked --no-default-features
cargo test --workspace --release --locked --all-features
cargo +1.85 check --workspace --all-targets --locked
cargo +1.85 check -p tyche-yield --lib --no-default-features --features wasm --target wasm32-unknown-unknown --locked
cargo +1.85 check -p tyche-market --lib --no-default-features --features wasm --target wasm32-unknown-unknown --locked
wasm-pack build crates/tyche-yield --release --target web --out-dir pkg --out-name tyche_yield -- --no-default-features --features wasm
wasm-pack build crates/tyche-market --release --target web --out-dir pkg --out-name tyche_market -- --no-default-features --features wasm
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
pnpm parity
pnpm e2e
node scripts/check-text.mjs origin/main
```

`pnpm test` runs the twin's and the app's unit tests and the tests of
the repository scripts; `pnpm parity` checks the WebAssembly build of
tyche-yield against the twin; `pnpm e2e` builds the app and runs the
browser tests, with the axe sweep, against `vite preview` on port 4176,
which `E2E_PORT` moves. CI also runs Lighthouse against the build and
builds the badges from the outputs (`scripts/badges.mjs`).

A failed check is not flaky until the exact same command passes on
rerun. When a check fails and the fix is not obvious, report it rather
than route around it: no skipped tests, no loosened thresholds, no `any`
to quiet the type checker.

## Data and licensing

- The bond universe is synthetic: fictional issuers, calibrated on
  aggregate statistics only. No per-security exchange series is
  committed.
- Bank of Russia data (key rate, RUONIA, the zero-coupon curve of federal
  loan bonds, inflation) keeps its attribution: a link to cbr.ru, and the
  Moscow Exchange credited as the curve's calculator.
- No Moscow Exchange market data is stored or displayed; no live exchange
  mode in the browser; no ratings from rating agencies and no Cbonds
  data.
- Every widget names its source; the interface keeps a persistent "demo,
  not investment advice" banner and a "Data and licensing" page.
- A legal rule encoded in an engine (tax, for one) cites the act, the
  article and the revision date, and is checked against the primary
  text.

## Measurements

- A number from a vendor, a blog or a model card is a hypothesis, not an
  input; check it on this project before relying on it.
- A metric's name says what is actually measured and how it aggregates.
- Every reported measurement names the commit it was taken on and the
  build it ran against, features included.
- Accessibility claims are only as wide as the test behind them: axe
  sweeps over named states, WCAG 2 contrast checks on a named list of
  colour pairs, and the docs claim that list, nothing more. APCA is out.

## Interface rules

- Labels are visible by default; `hideLabel` keeps them for assistive
  technology only; descriptions go through `description`.
- Values keep their own direction (`Ltr` for left-to-right runs); `lang`,
  `dir` and the theme are set before the first paint; fonts as in Stoa's
  README.
- The focus never falls to the body after an action (`keepFocusInPlace`
  or a named stable target). Shortcuts go through `useShortcuts` and
  Button's `shortcut`.
- The product proposes; a person decides anything regulated or
  irreversible, such as an order.

## Scope

- Do the task that was asked; list unrequested refactors, renames and
  dependency upgrades as suggestions instead.
- Dead code found during work is reported, not deleted.
- One change at a time when validating; two changes in one measurement
  cannot be told apart.
